# Contraction-heuristics talk

Trace-driven reveal.js deck built from `PROPOSAL.md` with the `tn-slide-deck` skill.
Python computes every figure once as `data/<id>.json`; the deck only draws it.

## Set up a fresh clone (once)

`deck/index.html`, `deck/vendor/`, `deck/media/` and the environments are not in git; build them first.

```sh
cd slides
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements.txt
PUPPETEER_SKIP_DOWNLOAD=1 PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install   # uses the system /usr/bin/chromium
sh export/vendor.sh                           # reveal.js, KaTeX, fonts → deck/vendor/ (offline deck)
.venv/bin/python export/build_deck.py         # deck/slides/*.html → deck/index.html   (required before serving)
sh export/render_clips.sh                     # optional: Manim clips → deck/media/ (a few minutes; needs TeX Live)
```

`data/*.json` is tracked, so the deck needs no recomputation; `.venv/bin/python -m traces.figures` rebuilds it.

## Run

```sh
.venv/bin/python export/build_deck.py         # after every edit of deck/slides/*.html or deck/shell.html
python3 tools/serve.py                        # port 8001; supports Range, so clips are seekable
# open http://localhost:8001/deck/   (S = speaker notes, F = fullscreen, ←/→ step, ↓ = clip under a slide)
```

Ctrl+C stops the server. Hard-reload (Ctrl+Shift+R) after a rebuild.

## Rebuild after a change

```sh
.venv/bin/python -m traces.figures            # regenerate data/*.json
.venv/bin/python traces/validate_trace.py data/*.json
.venv/bin/python -m pytest -q                 # every number on a slide is asserted here
.venv/bin/python export/build_deck.py         # deck/slides/*.html + deck/shell.html → deck/index.html
```

Edit slides in `deck/slides/<act>.html`, never `deck/index.html` (generated).

## Check before rehearsal

```sh
node export/shots.mjs [from to] [--last]      # PNG per fragment state → export/out/shots/ (PORT=<n> if not 8001)
node export/check_steppers.mjs                # forward / backward / re-entry consistency
.venv/bin/python export/lint_numbers.py       # digits typed into slides instead of bound
grep -rn "VERIFY:" deck/slides/               # claims still to check
```

## Conventions

- Numbers on slides come from `data-bind="F10:tree.cost"` (trace id : JSON path) or from a stepper reading its trace.
- Seeds: MinFill tie-breaks use `random.Random(seed)` over the graph's node order; grid numbers use seeds 0–9 on the
  integer-relabelled grid and report the first seed that reaches the minimum width.
- Colours: accent = what matters now, derived = fill/intermediates, side-b = other side of a cut, muted = background.

## Treewidth solvers (deep dive 4)

```sh
git clone --depth 1 https://github.com/TCS-Meiji/PACE2017-TrackA tools/PACE2017-TrackA
git clone --depth 1 https://github.com/maxbannach/Jdrasil tools/Jdrasil
(cd tools/PACE2017-TrackA && javac tw/heuristic/*.java)          # Tamaki et al. heuristic
(cd tools/Jdrasil && mkdir -p build/classes && javac -d build/classes $(find subprojects/core/src/main/java -name "*.java"))
.venv/bin/python -m traces.run_solvers          # anytime curve → data/S42.json (~7 min; timing-dependent)
.venv/bin/python -m traces.run_solvers small    # scorecard runs on the talk's circuit → data/S44.json (~1 min)
```

The solvers are called directly with a 2 GB heap (Tamaki's own `tw-heuristic` script reserves 30 GB) and stopped
with SIGTERM at the budget, as in PACE; every returned decomposition is validated in `traces/solvers.py`.
These two data files are not regenerated by the tests (they take minutes); the tests validate them.

## PDF and notes (venues without a working browser)

```sh
python3 tools/serve.py &                        # 8001
npm run pdf                                     # → export/out/deck.pdf, one page per click (every stepper state, math last)
.venv/bin/python export/notes.py                # → export/out/notes.md, speaker notes + source and test of every number
```

`?export` in the URL swaps each Manim clip for its poster frame, so clip pages show the clip's end state.
