# Reproduction notes: arXiv 2608.05819

Differences found between the paper and the authors' release (`alfred-miquel/LTR-Quantum-Contraction-Plans`
at `936630a`). "Paper" means the arXiv text; "code" means the release. We report what the code and data give;
we can't tell from them why they differ from the text. Numbers: `results/t06_t07.csv` and
`results/t06_t07_composition.csv`, regenerated by `experiments/t06_t07.py`.

## Phase 1: ranker on the published splits

**Reproduced exactly: Table 6, Top-1, Top-3, Regret1, Regret3 of both models**, in Python and with the
authors' Julia code (`experiments/julia/t06_t07.jl`), under these conditions, all from their Notebook 5:

| The paper says or implies | The code does |
|---|---|
| One model per row | Two models per row: `opt_ndcg` takes Top-1 and Regret1 from 1 round, Top-3 and Regret3 from 65; `opt_pair` from 16 and 14 |
| `opt_ndcg`: eta 0.01, subsample 0.7 (Table 4) | eta 0.02, subsample 0.8; Table 4's values never give the published Top-3 or regrets in rounds 1–300 |
| Regret on speedup, `1 - Sp_1 / Sp*` | Regret on the label, `log(1 + Sp)`. On speedup, no round matches, and MinFill's Regret1 is 0.1015, not 0.0735 |
| Labels `log(1 + Sp)` | Yes, natural log, then converted to integer ranks within each circuit before training |

No single model at any round from 1 to 300 gives all four published values in a row. The release doesn't show how the
round counts were chosen.

**One model per objective, rounds from grouped 5-fold CV on the training split alone**, over three fold
assignments and both `opt_ndcg` parameter sets:

Regrets here are on labels, to compare with the paper. The ID comparison with MinFill (Top-1 12%) holds up. On OOD
the Top-3 is close to choosing at random (52.2%, exact expectation on these splits). With 25 ID circuits one circuit is
4 points, and the chosen round count varied from 7 to 158 with the fold assignment, so these are ranges and not point estimates.

**Not reproduced**

- **Table 7.** No code for it in the release. On the training split alone, no round gives `opt_ndcg`'s values.
  Trained on train + ID, some rounds do jointly match Top-1 + Regret1 and Top-3 + Regret3 for `opt_ndcg` (11; 23, 24,
  135–138). For `opt_pair`, Top-1 + Regret1 match at round 54 on train + ID and Top-3 + Regret3 at round 14 on train
  alone. This suggests Table 7 is composed like Table 6, but it isn't established.
- **Win rate**, with our reading of it (plan ranked first against MinFill, ties half). No code in the release.
  `opt_ndcg` ID stays at 80–84 where the paper has 92.
- **The random and MinFill+random baselines.** No code in the release. Exact expectations on the published splits
  are random 16.13 / 46.40 / 0.0798 / 0.0204 / 56.95 against the paper's 22.95 / 58.44 / 0.0699 / 0.0137 / 70.16,
  and MinFill+random Top-3 44.93 against 28. MinFill's own Top-1 and Regret1 (12%, 0.0735) do match.
- **`mf_ndcg` baseline.** Not attempted.

**The stored models are not test evidence.** `models/opt_pair.json` is the Notebook 5 recipe fitted on all 225
circuits, ID and OOD included: predictions agree to under 1e-5 at 1850 rounds. `opt_ndcg.json` looks similar (Top-3
100% on OOD) but we didn't identify its exact parameters. The authors' README calls these production models, for which
that's a normal choice. They score far above the tables (Top-1 84–97%) for this reason, and Table 6 doesn't use them.
They rank well on the z-scored split features and poorly on raw ones (ID Top-1 8–16%), while their Notebook 4 passes raw values.

**Data**

- The split files cover 225 circuits, as the paper says, in 1475 rows. Features are standardised, not as in
  `Features.xlsx`; a z-score over the training rows doesn't recover them, so the scaler is unknown (for phase 2).
- `RQC_3_7_40` and `RQC_3_7_52` have plans listed twice in the training split (12 duplicated rows), with the same features but
  speedups differing by up to 0.84. They count as one group of 14 and one of 11.
- Three training circuits have no MinFill plan (`RANDOM_11`, `RQC_5_32`, `pricingcall_nativegates_ibm_qiskit_opt3_25`), though speedup is defined against it.
- `measures.xlsx` holds speedups against MinFill only (1367 rows), no raw times and no second GPU. It lacks 97 rows
  of the splits, and differs from them in 155 rows (up to 727.9, in QFT circuits). We use the split files.

**Library version matters.** xgboost 2.1.4 in Python matches their Julia stack (XGBoost_jll 2.1.5) to about 5e-8 in
predictions. xgboost 3.4.1 gives different models from the same inputs (differences of 0.03–1.06), so the project pins 2.1.4.
